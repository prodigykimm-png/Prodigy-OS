# 전국 경매 키값 CSV 자동 적용

## 사용 방법

1. 데스크톱 Obsidian의 Dusk Vault를 연다.
2. CSV 파일을 `INBOX/Auction CSV/`에 넣는다.
3. 적용 완료 알림을 확인한다.
4. 이후 열거나 생성하는 경매 카드에서 최신 키값을 사용한다.

AI 또는 외부 API를 호출하지 않는다. CSV 파싱, 중복 제거, 키값 계산과
스냅샷 갱신은 지정 Mac의 Obsidian 안에서 로컬로 실행된다.

## 카드 낙찰가 자동 반영

`PARA/PROJECTS/Auction/`의 경매 카드에 `winning_bid_price`(낙찰가)를
기록하면 키값 평균에 자동으로 누적된다. CSV와의 중복은 주소 표기(도로명·지번)
과 무관하게 `시도|시군구|동|종류|면적|가격|일자` 합성키로 제거되고, 같은
건물은 `동|건물명` 기준으로 하나의 건물로 계수된다.

카드 낙찰가만 있으면 되는 조건: 면적 확인, 과거 기일, 지원 물건종류, 동 해결.
미래 기일과 `정보 없음` 동 값은 제외된다. 예정 입찰가·희망가는 평균에
반영되지 않는다.

## 예외 정책 (선결정 계약)

충돌·예외는 감시가 아니라 아래 정책으로 즉시 처리한다. 새 예외를 발견하면
이 표에 추가하는 것이 원칙이다.

| 예외 | 정책 | 근거 |
|---|---|---|
| 합성키 충돌 (동·종류·면적·가격·일자가 완전히 같은 두 물건) | 동일 표본으로 간주, 중복 제거 | 같은 평단가라 평균값 손실 없음, 표본 수만 감소. 감사 `card_duplicates`로 관측 |
| `lost` 카드의 `winning_bid_price` | 포함 | 그 경매의 실제 타인 낙찰가 = 유효 시장 표본 |
| 면적이 평 단위 단독 표기 (`25.4평`) | ×3.305785로 ㎡ 자동 환산 | 단위 의미 명확. `㎡(평)` 병기는 ㎡ 우선 |
| 콤마 표기 낙찰가 (`210,000,000`) | 콤마 제거 후 정수 파싱 | 표기 차이일 뿐 값 손상 없음 |
| `region_dong` 다중 접두사 (`수원시 권선구 권선동`) | 접두사 반복 제거 | CSV는 법정동만 저장하므로 단일 동이어야 매칭 |
| 이중 계수 방지 불가 케이스 | 발생 시 감사로 확인 후 이 표 갱신 | 임의 판단 금지 |

## 입력 계약

CSV에는 다음 열이 필요하다.

- `물건종류`
- `소재지`
- `건물면적`
- `낙찰가`
- `매각기일`

토지 물건의 키값을 계산하려면 `대지권` 값도 필요하다. 지역은 별도 목록으로
제한하지 않고 `소재지`에서 시도·시군구·법정동을 읽으므로 전국 데이터를
동일한 방식으로 처리한다.

지원 물건종류는 아파트, 오피스텔, 다가구, 다세대(빌라), 주택(단독주택 포함), 근린상가, 근린주택, 근린시설, 숙박(콘도등·숙박시설), 노유자시설, 지식산업센터, 공장과 토지 계열이다. 비부동산(차량·선박·중장비 등)은 제외된다.
동일한 낙찰 건은 결정적 `record_id`로 중복 제거한다.

## 적용 결과

- 누적 정규 레코드:
  `SYSTEM/CACHE/auction-key-value/current/normalized.json`
- 계산 스냅샷:
  `SYSTEM/CACHE/auction-key-value/current/snapshot.json`
- 처리 감사 기록:
  `SYSTEM/CACHE/auction-key-value/current/audit.json`
- 카드가 읽는 스냅샷:
  `SYSTEM/Views/auction-key-value-snapshot.js`
- 처리 완료 CSV:
  `INBOX/Auction CSV/Processed/YYYY-MM/`

새 CSV는 기존 정규 레코드와 병합하므로 지역을 여러 파일로 나누어 넣어도 된다.
기존 스냅샷의 원본 정규 레코드도 최초 실행 시 자동으로 승계한다.

## 성능 계약 (선결정)

- **쓰기 생략**: 스냄샷/카드스냄샷/감사 기록은 데이터가 변했을 때만 기록한다.
  `generated_at`과 소요시간은 데이터 해시에서 제외되므로, 데이터 불변인 재계산에서는
  어떤 출력 파일도 다시 쓰지 않는다 (iCloud 동기화 유발 방지).
- **카드 이벤트 병합**: 카드 수정 연타는 1.5초 trailing debounce로 합쳐져
  마지막 1회만 실행한다. CSV 이벤트는 즉시 실행한다.
- **카드 스캔 캐시**: 카드 본문은 `vault.cachedRead`로 읽어 메모리 캐시를 재사용한다
  (반복 실행에서 디스크 재독 없음, 수정된 카드만 캐시 무효화).
- **원자적 normalized 쓰기**: `normalized.json`은 tmp → rename으로 기록한다.
  중단으로 tmp가 남으면 다음 실행의 `existingRecords`가 자동 복구한다.
- **소요시간 측정**: 모든 재계산의 `duration_ms`가 `audit.json`에 기록된다.

## 실패 처리

필수 열 누락이나 잘못된 값 때문에 적용에 실패하면 스냅샷을 갱신하지 않고
CSV를 입력 폴더에 남긴다. Obsidian 알림에 표시된 문제를 수정한 뒤 같은 파일을
다시 저장하면 자동으로 재처리된다.
