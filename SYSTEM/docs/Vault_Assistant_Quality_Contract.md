# Vault Assistant 품질·운영 계약

적용 버전: 0.2.0. 이 문서는 읽기 전용 Vault Assistant에만 적용한다.

## 답변 일관성

- 동일한 질문과 문서 스냅샷에는 결정적인 근거 선택을 사용한다. 파일 열거 순서에 따라 근거가 바뀌지 않는다.
- 반복 질문도 현재 문서를 다시 확인한다. 저장된 답변을 사실 근거로 재사용하지 않는다.
- 문서 수정·삭제·메타데이터 변경과 저장되지 않은 편집 내용은 다음 검색에 반영한다.
- 질문, 범위, 지정 문서, 대화 소유권은 제출 시 고정한다. 늦게 끝난 요청이 다른 문서나 대화의 답변으로 저장되지 않는다.
- 현재 문서 전환 시 진행 중인 해당 문서 요청을 취소하고 표시 경로를 갱신한다. 같은 탭 안의 파일 전환도 포함한다.
- 응답 후 저장하기 전에 출처를 다시 확인한다. 바뀌거나 삭제된 출처는 정상 출처로 표시하지 않는다.
- 모델 문구의 완전한 동일성은 보장하지 않는다. 사실·조건·수치·출처의 일관성을 평가한다.

## 근거 선택과 성능

- 제공자에게 전달하는 근거 JSON은 최대 8 KiB, 개별 조각은 최대 2 KiB다. 선택과 전송이 같은 바이트 계산을 사용한다.
- 현재 문서와 지정 문서의 전체 근거가 예산 안에 들어오면 조각 개수 제한으로 일부를 버리지 않는다.
- 예산을 넘는 현재 문서는 질문에 관련된 서로 다른 문서·내용을 우선 선택한다.
- 전체 Vault는 로컬 키워드·메타데이터 점수와 한 단계 문서 링크 확장을 사용한다. 최대 6개 조각, 문서당 최대 2개로 문서 다양성을 유지한다.
- 파일 읽기 성공과 근거 선택 범위는 별개다. 일부 근거만 선택했다면 화면에 조각 수와 범위 제한을 표시한다.
- 변경되지 않은 파일의 내용·해시·준비된 조각은 메모리에서 재사용한다. 디스크 영구 인덱스와 외부 임베딩 호출은 없다.
- 대화의 과거 사실이나 문서 안의 지시문은 실행 지시로 취급하지 않는다.

## 요청과 복구

- 질문 한 번에 기존 전역 AI Runtime을 통한 구조화 요청 한 번만 실행한다.
- 중복 제출은 같은 진행 작업으로 합친다. 자동 재시도·자동 재개·제공자 전환은 없다.
- 명시적 재시도는 이전 제출의 질문과 범위를 유지하고 새 시도 식별자를 사용한다.
- 취소와 60초 제한은 로컬에서 요청 상태를 종료한다. 원격 취소 성공을 기다리며 화면을 잠그지 않는다.
- 검색 중과 답변 생성 중을 구분한다. 오류는 복구 동작과 함께 표시한다.
- Assistant 열기 명령은 기존 화면을 재사용한다. 화면을 다시 열었다고 새 대화 상태를 덮어쓰지 않는다.

## 변경 시 검증 기준

패키지 디렉터리에서 다음 검증을 모두 실행한다.

```sh
bun run typecheck
bun run lint
bun test
bun run build
bun run audit:mobile
```

실제 Obsidian 회귀:

```sh
node SYSTEM/AI/Skills/prodigy-review/tests/shared/test_vault_assistant_real_obsidian.js
```

실제 제공자 평가에서는 여러 섹션에 답이 흩어진 문서를 사용한다. 같은 질문 두 번과 동등한 다른 표현 한 번을 제출해 필요한 사실·조건의 누락과 서로 모순되는 답변이 없는지 확인한다. 문서 변경 후에는 새 사실을 반영하고 이전 출처 상태가 드러나는지도 확인한다. 평가 요청은 명시적으로 실행하며 백그라운드 AI 검사를 추가하지 않는다.

실기기 iPhone·iPad 검증과 원격 CI 실행은 별도 증거가 필요하다. 데스크톱의 논리적 화면 크기 시험으로 실기기 성공을 대신하지 않는다. 인용 식별자와 출처 해시 검증은 필요조건이며, 답변의 의미적 정확성까지 자동으로 보증하지는 않는다.
