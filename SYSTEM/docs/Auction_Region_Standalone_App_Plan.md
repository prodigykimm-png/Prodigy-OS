# 옥션·지역 독립 앱 계획 (초안 v0.2, 2026-10-28)

## 1. 목표

Obsidian 안의 옥션·지역 워크스페이스를 하나의 독립 앱으로 옮겨 Dataview 병목 없이 빠르게 쓴다.

- 지원 플랫폼: Windows, macOS, Android, iOS. **Mac과 iOS를 먼저** 맞춘다.
- 사용자: 지금은 나 혼자. 공유와 앱스토어 배포는 앱이 어느 정도 완성된 뒤.
- 1차 목표는 **AI 없이 제대로 작동하는 앱**이다. AI 기능(입찰 판단 보조, 지역 질문, 임장 기록 정리)은 나중에 붙인다.

## 2. 출발점 (2026-10-28 실측)

| 항목 | 규모 |
|---|---|
| 옥션 카드 | 539장, 마크다운 약 4.4MB |
| 지역 노트 | 230개, 약 7.9MB |
| 키값 스냅샷 | `auction-key-value-snapshot.js` 4.6MB |
| 화면 코드 | 옥션 뷰 43개, 지역 뷰 28개, 지역·지가·교통 스크립트 약 70개 |

데이터 자체는 작다. 느린 원인은 크기가 아니라 다음 네 가지다.

- Dataview 인덱싱 대기
- `dataviewjs` 블록 재실행
- 큰 JS 스냅샷
- iCloud 온디맨드 다운로드

정규화가 필요한 데이터도 있다. `status`에 따옴표가 있는 값과 없는 값이 섞여 있고, 상태가 깨진 카드가 2장 있다. frontmatter 가드(`auction-frontmatter-guard-cli.js --check`) 기준으로는 539장 중 6장이 깨져 있다(값 따옴표 누락). 가져오기 전에 백업한 뒤 수선하거나, 가져오기 프로그램이 이런 값을 받아들여야 한다.

### 3.1 완전 무료 구성

원본 데이터는 내 Mac에만 둔다. Mac이 꺼져 있어도 돌아가야 하는 두 가지(공유 링크, 입찰일 알림)만 Cloudflare 무료 플랜에 맡긴다.

```
 [iPhone · PWA] ── Tailscale(무료 VPN) ──> [내 Mac]
   화면은 Cloudflare Pages에서 받음        PocketBase = 원본 DB·사진
   데이터는 폰에 먼저 저장                 사건번호 조회 · data.go.kr 조회
                                                │ 공유 사본·알림 일정만 업로드
                                                ▼
 [Cloudflare 무료] Pages = 앱 화면 · Workers = 공유 링크·알림 발송 · KV = 공유 사본·알림 일정
                                                │
                                                ▼
 [외부 사람] 링크만 열면 웹에서 카드 보기 (계정·앱 필요 없음)
```

무료 한도 (공식 문서, 2026-10-28 확인):

| 역할 | 서비스 | 무료 한도 | 내 사용량 예상 |
|---|---|---|---|
| 기기 연결 | Tailscale Personal | 영구 $0, 기기 무제한, 최대 6명 | Mac + iPhone |
| 동기화 DB | PocketBase (Mac 실행) | 오픈소스 | — |
| 앱 화면 배포 | Cloudflare Pages | 무료 플랜 | 정적 파일 몇 MB |
| 공유 링크·알림 | Cloudflare Workers | 하루 요청 10만 | 하루 수십 |
| 공유 사본·알림 일정 | Workers KV | 읽기 하루 10만, 쓰기 하루 1,000, 저장 1GB, 값 하나 25MB | 사본 수 KB, 쓰기 하루 수십 |
| 지도 | 카카오맵 | 지도 하루 30만, 로컬 API 하루 10만 | 주소 변환 539건 1회 |
| 건축물·실거래 | data.go.kr | 무료(키 발급) | 사건당 몇 건 |
| 사건번호 조회 | 법원경매정보 | 무료 | 하루 수십 건 이내 |
| 푸시 | 웹 푸시(VAPID) | 발송 무료 | 하루 1~2건 |

R2는 쓰지 않는다. 활성화 때 결제 수단 등록이 필요한지 확인하지 못했고, 카드 사본은 KV로 충분하다.

무료의 대가:
- Mac이 꺼져 있으면 기기 간 동기화가 멈춘다. 폰에서 고친 내용은 폰에 저장됐다가 Mac이 켜지면 올라간다. 공유 링크와 알림은 Mac과 무관하다.
- 밖에서 최신 데이터를 받으려면 iPhone의 Tailscale을 켜 둔다.
- PWA는 앱 화면이 열려 있는 동안만 위치·동선을 기록한다. 백그라운드 동선은 네이티브 앱(Apple 개발자 계정)이 필요하다.
- 서명 없는 Mac·Windows 앱은 첫 실행 때 경고가 뜨고, 한 번 허용하면 된다.
- 백업은 Time Machine과 앱의 md/JSON 내보내기로 직접 챙긴다.
- 무료 정책은 바뀔 수 있다. 그래서 Cloudflare에는 원본을 두지 않는다.

돈이 들게 되는 순간 (지금은 해당 없음): iOS 네이티브·백그라운드 동선·서명된 Mac 앱(Apple 개발자 연 $99), Play 스토어(1회 $25), 내 도메인(선택, 연 1~2만 원), Mac 없이 돌아가는 클라우드 DB(PocketHost 월 $9.99 등).

## 4. 기존 규칙 중 앱으로 그대로 가져갈 것

- 모든 카드가 같은 필드를 같은 순서로 보여 준다. 값이 없으면 `-`로 표시하고 블록을 숨기지 않는다.
- 수익 필드 `출구가 · 차익 · 월수익`은 값이 비어 있어도 필드별로 눌러서 편집할 수 있어야 한다.
- `최저가`와 `입찰 예정가`는 원 단위까지 정확히, 한 줄에 나란히 보여 준다.
- `보증금`은 `최저가 ÷ 10`으로 계산되는 값이라 편집할 수 없다.
- 가격 데이터는 내 입찰 감각을 보정하는 용도이지 가격 예측이 아니다. 범위만 보여 주고 "입찰하세요" 같은 지시는 하지 않는다.
- Apple 기본 앱 문법을 따른다: 리스트·행·구분선, 파란색은 선택과 주요 동작에만, 카드 안에 카드를 넣지 않는다.

### 4.1 임장 체크리스트 (현재 Obsidian 구조)

- **평가값:** 미평가 / 상 / 중 / 하 / 관계없음. 항목마다 메모를 달 수 있다.
- **공통 13개:** 주변 환경, 건물 상태, 공용부, 접근성, 주차, 소음, 냄새, 사진, 관리사무소, 중개사 인터뷰, 예상 밖 발견, 점유 상태, 전체 분위기
- **물건 종류별 추가 항목:**
  - 아파트: 호실 구조, 채광, 조망, 보안, 엘리베이터
  - 오피스텔: 아파트 항목 + 주차 방식, 관리비, 관리 인력 상주, 실제 주거 이용, 냉난방 방식
  - 다세대·다가구·연립: 호실 구조, 공동 현관, 주차 수용력, 관리 상태, 임차 상태
  - 근린·상가: 고객 접근성, 상권 노출도, 기반시설, 소방 안전
  - 상업: 도로 노출도, 보행자 흐름, 임차인 구성, 하역 접근성
  - 숙박(생활숙박·호텔): 프런트 운영, 위탁운영 계약, 객실 상태, 소방·피난, 공용시설 운영, 관리비, 실제 숙박 운영
  - 토지: 도로 접근성, 토지 경계, 경사, 배수, 인접 토지 이용
  - 공장·지식산업센터: 차량 접근성, 전력 공급, 층고, 하역 공간, 설비 상태
- **우선 항목:** 물건 종류마다 먼저 봐야 할 5~6개가 따로 정해져 있다(`PRIORITY_ITEMS`). 앱에서는 이 항목을 체크리스트 맨 위에 둔다.
- **함께 저장하는 것:** 관리사무소 연락처(이름·전화·메모), 자유 메모, 예상 밖 발견, 사진, 시작·종료 시각
- **원본 위치:** 카드 본문의 `<!-- PRODIGY_SITE_VISIT_STATE ... -->` 블록(상태 version 3). 입찰 당일 화면(`auction-day-view.js`)도 이 데이터를 쓴다.
- **이전:** 임장 기록이 남아 있는 카드 11장은 P1 가져오기에서 이 블록을 그대로 `field_visits`로 옮긴다. 예전 값(체크 표시 → 중)은 이미 정규화 규칙이 있다.

## 5. 데이터 모델 (초안)

모든 레코드에 `owner_id`를 둔다. 나중에 공유 기능을 붙일 때 DB를 갈아엎지 않기 위해서다.

| 엔티티 | 내용 |

| `notification_schedule` | 입찰일 알림 일정(사건, 발송일, 종류 D-3/D-1)과 웹 푸시 구독 정보. KV에 올리는 원본 |

## 6. 단계

| 단계 | 내용 | 끝났다고 볼 기준 |
|---|---|---|
| **P0** | 결정 확정, 수집 방식 조사 | 이 문서 승인 + 7장 조사 반영 |
| **P1** Mac 읽기 전용 | 새 저장소, md→SQLite 가져오기(정규화 포함), 오늘·보드·지역 화면 | 가져온 개수가 md 개수와 일치(539 / 230). Mac에서 앱을 켜서 첫 화면이 뜨기까지 시간을 Obsidian과 나란히 실측 비교 |

## 7. 사건번호 자동 수집 — 조사 결과 (2026-10-28)

**결론:** 개인용으로는 난이도가 낮고 추가 비용이 없다. 사건번호로 법원경매정보를 조회하는 오픈소스 패키지를 이미 볼트 스크립트가 쓰고 있어서, 이것을 Mac 서버에 연결하면 된다. 공유·배포용으로 서버 한 곳에서 모든 사용자 조회를 대신하는 방식은 차단 위험과 법적 미확정 때문에 지금은 권하지 않는다.

확인한 사실 (직접 조회):
- `SYSTEM/SCRIPTS/real-estate-source-collect.js`는 `court-auction-notice-search`(npm 최신 0.3.3, 저장소 `NomaDamas/k-skill`)를 커밋 해시로 잠가 두고 쓴다. 잠금 파일은 `SYSTEM/CONFIG/k-skill-real-estate-lock.json`이고, 커밋은 `06d017ac…`다.
- README 기준 지원 범위:
  - **사건번호 직접 조회**로 사건정보, 물건내역, 매각기일내역, 배당요구종기를 가져온다.
  - 매각공고 검색과 조건 검색(지역·용도·가격·면적·유찰횟수)도 된다.
  - 연결은 직접 HTTP가 1순위이고, 막히면 브라우저 자동화(Aside → BrowserOS → Chrome)와 Playwright로 넘어간다.
- **지원하지 않는 것:** 물건 사진, 매각물건명세서 PDF, 감정평가서 PDF.
- **차단:** 비정상 접근이 감지되면 사이트가 "1시간 후 다시 시도" 차단을 건다(`ipcheck: false`, 패키지 테스트 fixture). 패키지는 이를 피하려고 호출 간에 2초 이상 간격을 두고 세션당 10회로 제한한다.
- `courtauction.go.kr/robots.txt`는 없다(404, 시스템안내 페이지). 이용약관은 읽지 못했다.
- 기존 스크립트는 건축물·실거래 조회 일부를 제3자 프록시(`k-skill-proxy.nomadamas.org`)를 거쳐 한다. 앱에서는 내 data.go.kr 서비스키로 바꾸는 편이 안전하다.

경로별 비교:

| 경로 | 채우는 필드 | 비용 | 난이도 | 위험 |
|---|---|---|---|---|
| 법원경매정보 (위 패키지, Mac 서버) | 사건·법원·주소·용도·감정가·최저가·기일·진행상태 | 0원 | 낮음 (코드 있음) | 소량이면 낮음. 과다 호출 시 1시간 차단 |
| data.go.kr 건축물대장·실거래 | 건물 연식·용도·면적·시세 참고 | 0원 (키 발급 필요) | 낮음 | 낮음 (공식 API) |
| 옥션원 등 상용 사이트 (aside) | 사진·권리분석·명세서·감정평가 | 기존 구독료 | 이미 운영 중 | 약관상 자동 수집 금지 가능성 (미확인) |

권장 경로:
- **지금(개인용):** 앱에서 사건번호와 법원을 입력한다 → Mac 서버가 법원경매정보와 data.go.kr로 카드 초안을 만든다 → 사진과 권리분석은 기존 aside 경로로 보강한다. 하루 수십 건 이내로 두고 결과를 캐시한다.
- **나중(공유·배포):** 서버 한 곳에서 모든 사용자 조회를 대신하면 한 IP에 호출이 몰려 차단될 가능성이 높다. 각 사용자 기기에서 직접 조회하는 방식을 검토하고, 배포 전에 이용약관과 법률 검토를 한다.

확인하지 못한 것:
- 법원경매정보 이용약관
- 상용 경매 사이트의 API 제공 여부와 가격, 약관
- 크롤링 관련 판례(잡코리아 v. 사람인, 야놀자 v. 여기어때)의 정확한 결론
- 전용면적이 사건 조회 응답에 들어 있는지

실제 조회 확인 (2026-10-28, 카드 2025타경101240, 안양지원 `B000254`, 1회 66ms):
- 패키지는 지금 정상 동작한다. 사건번호 조회는 HTTP만 쓰고 브라우저로 넘어가지 않는다.
- 원본 응답에 감정가(499,000,000), 다음 매각기일(2026-11-10, 3회차), 현재 최저가(255,488,000), 보증금률(10%), 담당 계(경매1계)와 전화, 건물명·도로명 주소, 이해관계인 19명, 매각물건명세서 문서 ID가 있다.
- 패키지의 정리 단계는 가격·기일을 빈칸으로 돌려준다. 앱은 원본 응답(`dlt_dspslGdsDspslObjctLst`, `dlt_rletCsGdsDtsDxdyInf`, `dma_csBasInf`)을 직접 읽는다.

조사 기록: 1차 InferHub 실행은 공급자 용량 부족(503)으로 실패했다. 2차 Sonnet 5.5 실행은 작업 자체의 쉘 도구가 고장 나서 웹 조회를 하지 못했다. 위 확인 사실은 부모 세션에서 직접 조회한 것이다.


## 8. 알려진 위험

- **PWA 저장소와 웹 푸시의 안정성:** 아직 확인하지 않았다. P3 초반에 실제 기기로 먼저 검증한다.
- **알림은 Mac이 아니라 Cloudflare Worker가 보낸다.** 앱이 알림 일정을 KV에 올려 두지 않으면(예: 마지막 동기화 후 새로 생긴 기일) 그 알림은 빠진다. 카드의 기일이 바뀔 때마다 일정을 다시 올린다.
- **PWA는 백그라운드에서 위치를 기록하지 못한다.** 임장 동선은 화면이 열려 있는 동안만 기록된다.
- **무료 정책은 바뀔 수 있다.** Cloudflare에는 공유 사본과 알림 일정만 두므로, 바뀌어도 잃는 것은 그 두 기능뿐이다.
- **카카오 지도 키는 등록한 웹 도메인에서만 작동한다.** PWA 주소(`*.pages.dev`)는 등록하면 되지만, Tauri 데스크톱 앱 내부 주소(`tauri://localhost` 등)를 받아 주는지는 확인하지 않았다. P4 시작 때 먼저 검증한다.
- **iCloud 폴더 안에 앱 코드를 두면 안 된다.** `node_modules`와 빌드 산출물이 동기화를 망가뜨린다. 저장소는 볼트 밖(예: `~/Developer/`)에 둔다.
- **이전 기간에는 원본이 두 개가 되는 순간이 있다.** md 입구가 열려 있는 동안 같은 카드를 Obsidian과 앱에서 동시에 고치지 않도록, P1 이후에는 카드 편집을 앱 한쪽에서만 한다.
